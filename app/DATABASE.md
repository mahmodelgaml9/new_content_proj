# CMO-Prime: Database Schema

## ORM

We use **Prisma** as our Object-Relational Mapper to provide a type-safe interface for our PostgreSQL database. The schema is the single source of truth for our data models.

## Core Models & Relations

*   `User`: Stores user credentials and profile information. A `User` can own multiple `Business` entities.
*   `Business`: The central entity. It holds the core business data and has one-to-one or one-to-many relationships with all analysis and planning modules.
*   `MarketAnalysis`, `BrandIdentity`, `CustomerBlueprint`: These are one-to-one relations with `Business`, storing the results of the initial diagnosis.
*   `MarketingPlan`: A `Business` can have many `MarketingPlan`s, representing different strategic scenarios.

## The "Specialized Experts" Architecture

This is the core of our execution engine. Instead of one generic plan, each `MarketingPlan` is linked to multiple, specialized execution plans.

*   **`ContentExecutionPlan`**:
    *   Represents the monthly plan generated by the "Content Commander".
    *   Linked to a `MarketingPlan`.
    *   Contains a `month` field and a `planContent` JSON field.
    *   The `planContent` holds the detailed daily tasks, keywords, hooks, CTAs, etc.

*   **`GeneratedContent`**:
    *   Represents a single piece of generated content.
    *   Crucially, it is linked back to the `ContentExecutionPlan` and contains the `taskId` and `variationNumber` from which it was generated, providing full traceability.

*   **Future Experts (e.g., `AdExecutionPlan`, `SeoExecutionPlan`):**
    *   These will follow the same pattern, being created as new, specialized models linked to the parent `MarketingPlan`. This structure is clean, organized, and highly scalable.
